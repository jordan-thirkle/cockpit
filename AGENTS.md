# AGENTS.md — Cockpit

Operational contract for AI agents (and future sessions) working on **Cockpit**,
the bespoke Hermes Agent dashboard shell by By JTT.

> Read this first. It encodes the hard-won facts so you don't re-derive them
> (and so you don't break the running dashboard by guessing).

## What Cockpit is

A **separate React 19 + TypeScript + Vite SPA** served *by* the stock
`hermes dashboard` backend via the `HERMES_WEB_DIST` env var. Cockpit never
modifies, forks, or patches Hermes. It rides the existing `/api/*` and
`/api/pty` endpoints.

- Source: `D:/Projects/cockpit` (Windows dev box)
- Built output: `dist/` (regenerated by `npm run build`; **gitignored**)
- Served at: `http://192.168.1.155:3001` (Windows LAN IP, basic-auth gated)
- Login: user `jordan`, password set in `config.yaml dashboard.basic_auth`
- Repo: `https://github.com/jordan-thirkle/cockpit.git` (private)

## The ONE rule that prevents breakage

**Never edit Hermes source to add a feature.** If a feature needs a new backend
endpoint (e.g. `/chat?prompt=`, cron list, MCP management, a REST "create
session"), that is a **Hermes-core change** and is OUT OF SCOPE for this repo.
Implement in Cockpit against the endpoints that already exist (below), or mark
the card **Guided** and open a chat with a prepared prompt (see
`ControlCenter.tsx` `openChat`). A *new chat* in Hermes is just a fresh PTY
terminal — Cockpit's "New chat" opens one (`ChatPanel` with `session={null}`).

## Verified backend contract (what you can call on `hermes dashboard`)

All paths relative to the dashboard base. Auth: cookie (`hermes_session_at`)
in gated/LAN mode, or injected `__HERMES_SESSION_TOKEN__` on loopback.

| Capability | Endpoint | Notes |
|---|---|---|
| Login (basic) | `POST /auth/password-login` `{provider:"basic",username,password,next:"/"}` | returns `{ok}` |
| Session check | `GET /api/auth/me` | 401 = not logged in |
| List sessions | `GET /api/sessions?limit=&offset=&order=recent` | ✅ used |
| Session detail | `GET /api/sessions/{id}` | structured per-session data |
| Rename/delete/archive | `PATCH/DELETE /api/sessions/{id}`, `…/archive` | ✅ used |
| Session messages (trace) | `GET /api/sessions/{id}/messages?limit=500&order=oldest` | ✅ used (TraceView) |
| Memory status | `GET /api/memory` | ✅ used (MemoryPanel) |
| Config schema | `GET /api/config/schema` | ✅ used (ControlCenter) |
| Providers | `GET /api/providers/oauth` | ✅ used (best-effort) |
| **Model list** | `GET /api/model/options?include_unconfigured=1` | `{model, provider, providers:[{slug,name,models[],is_current}]}` — verified live |
| **Model set** | `POST /api/model/set` `{scope:"main",provider,model}` | writes config.yaml, applies to NEW sessions only — verified live (`ok:true`) |
| **Skills listing** | `GET /api/fs/list?path=skills` | ⚠️ path is `/api/fs/**list**`, response `{entries:[{name,path,isDirectory}]}` (camelCase) |
| File read | `GET /api/fs/read-text?path=…` | response `{text,…}` |
| **File write** | `POST /api/fs/write-text` `{path, content}` | ⚠️ field is **`content`** (NOT `text`); backend does **NOT** auto-create parent dirs |
| PTY websocket | `ws(s)://host/api/pty?channel=&ticket=` | ticket from `POST /api/auth/ws-ticket` in gated mode |
| WS ticket | `POST /api/auth/ws-ticket` | returns `{ticket,ttl_seconds}` |

### Three historical bugs (do not reintroduce)

1. **`/api/fs/write-text` field name.** Cockpit originally sent `text` → every
   metadata write silently failed (400/422) and fell back to per-browser
   localStorage. The backend model field is **`content`**. `writeJsonFile` in
   `src/lib/hermesApi.ts` is already fixed — keep it that way.
2. **Parent dir must exist.** The backend will not create `data/cockpit/`.
   It was created once on the Windows box at
   `C:/Users/jorda/AppData/Local/hermes/hermes-agent/data/cockpit/`. If
   persistence ever stops working, confirm that directory still exists.
3. **"New chat" must open a terminal, not null.** Setting `activeSession` to
   `null` (which is already its default) rendered a blank pane. Use the
   `newChat` state in `App.tsx` to mount a fresh `ChatPanel` (PTY).

## Persistence model

Cockpit metadata (folder assignments, repo links, onboarding-seen flag) is
stored **server-side** outside Hermes's `state.db`, in
`HERMES_HOME/data/cockpit/*.json`, via `writeJsonFile`/`readJsonFile`.
This is why folder assignments survive `hermes update` and restarts.

`HERMES_HOME` on the Windows box is
`C:/Users/jorda/AppData/Local/hermes`. The dashboard's working dir (and thus
the `_fs_path` root) is `…/hermes-agent/`, so `data/cockpit` resolves to
`…/hermes-agent/data/cockpit`.

## Serving / deployment (how 3001 stays alive)

`HERMES_WEB_DIST` points at `D:/Projects/cockpit/dist`. The dashboard is run as
a **SYSTEM Scheduled Task** `\Hermes Dashboard LAN` (boot trigger) that calls
`C:/Users/jorda/AppData/Local/hermes/launch_dashboard.bat`. The bat:

- `cd`s into `hermes-agent`, sets `HERMES_WEB_DIST=D:/Projects/cockpit/dist`,
  unsets `HERMES_DESKTOP` (avoids the Electron "Desktop IPC bridge unavailable"
  error), unsets `HERMES_DASHBOARD_OAUTH_CLIENT_ID` (avoids the "Auth provider
  'nous' unreachable" error), and runs
  `hermes dashboard --port 3001 --host 0.0.0.0 --no-open --skip-build` in a
  self-healing loop.

To relaunch after a Cockpit change:
```bash
cd D:/Projects/cockpit && npm run build
schtasks /run /tn "\Hermes Dashboard LAN"   # or restart the task
```
